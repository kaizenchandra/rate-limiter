# Distributed failure scenarios

Guarantees assume a healthy authoritative primary, reserved memory, no foreign writes/eviction and one hash slot. Policy
staleness and floating arithmetic are explicit. No row below implies an unexecuted chaos drill has passed.

| Scenario                          | Mechanism and user impact                                                        | Detection                                                  | Mitigation / recovery                                                                                                               | Test strategy and residual risk                                                                                                                                                                                    |
|-----------------------------------|----------------------------------------------------------------------------------|------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1. Race for final token           | Concurrent consumers could overspend with client read/write                      | Accepted-count invariant                                   | Lua serializes check/deduction                                                                                                      | Real Redis two-client 1000-call contention; one winner per final token; state-loss exclusions remain                                                                                                               |
| 2. 1000 instances, one identity   | Hot slot queues and times out; Redis serialization preserves healthy-state quota | Redis CPU, decision tails, queue/bulkhead rejection        | Bounded concurrency; partition budgets or eligible leases; shed upstream                                                            | 1000 requests tested with two adapter objects, not 1000 pods; actual fleet contention drill remains                                                                                                                |
| 3. Redis unavailable              | No authoritative balance; 503 CLOSED or OPEN admission                           | Redis errors, fallback mode, readiness                     | No consume retry; bounded calls; restore Redis and verify state before readiness                                                    | Real refusal/timeout tests plus policy behavior unit tests; OPEN has unbounded extra admissions unless upstream limits apply                                                                                       |
| 4. Primary fails mid-consume      | Response unknown, data may or may not replicate                                  | Redis role/topology events, timeouts                       | CLOSED, no refund/retry; reconnect to authoritative owner                                                                           | Replica promotion drill script; abrupt mid-write failure is not exhaustively tested                                                                                                                                |
| 5. Failover rollback              | Lost acknowledged deductions can replenish quota                                 | Replication lag/offset and failover events                 | Conservative quotas, persistent managed topology, replica-lag alarms; rebuild or pause affected domain                              | Restart state-loss test proves limits can reset. If lag window is W and admitted rate a, exposure roughly <=aW plus burst; no finite bound if lag unbounded. WAIT reduces risk but does not give durable consensus |
| 6. Timeout after processing       | Caller sees error even if tokens consumed                                        | Timeout counters, traces, Redis balances                   | Never automatically repeat; return unknown/unavailable under CLOSED                                                                 | Real CLIENT PAUSE timeout; unit test verifies no retry. Some quota may be wasted                                                                                                                                   |
| 7. Pod crashes with lease         | Unspent prepaid tokens lost                                                      | Pod restarts, grant/spend difference                       | No reclaim/refund; quota naturally refills                                                                                          | Lease expiry simulates abandoned grant; kill-pod drill remains. <=16 wasted tokens/held bucket                                                                                                                     |
| 8. Cluster resharding             | MOVED/ASK/redirection; transient unavailability                                  | Lettuce topology events, redirect errors                   | Same-slot script, adaptive/periodic refresh, max two redirects; fail closed on exhausted routing                                    | Cluster same-slot/CROSSSLOT test; live reshard load drill remains; multiple related keys can produce TRYAGAIN during migration                                                                                     |
| 9. Hot tenant                     | One primary saturates despite spare shards                                       | Per-shard CPU/latency and external tenant traffic analysis | Dedicated domain, statically partition budget, approved leases, reject earlier                                                      | k6 hot/Zipf scripts; hot-key target scale not tested                                                                                                                                                               |
| 10. Quota changes in flight       | Old and new snapshots coexist                                                    | Revision/audit history, propagation failures               | 1s polling, 5s stale cutoff, stable bucket balance, newer observed consumption revision fence, conservative transition rate         | Revision/capacity tests; accepts under old policy before fence are possible; disabling rules needs propagation boundary                                                                                            |
| 11. Policy expiry                 | Baseline has disable tombstones, not wall-clock expiration                       | Audit desired/current versions                             | Use authorized disable; wait propagation; keep fail-closed fallback policies                                                        | Automatic validFrom/validTo scheduling is not implemented; no implicit expiration guarantee                                                                                                                        |
| 12. Two regions, same quota       | Independent Redis full buckets multiply allowance                                | Reconcile regional configuration and acceptance totals     | Partition C and r; no automatic budget duplication on failover                                                                      | Multi-region WAN drill remains; current code provides only independent regional domains                                                                                                                            |
| 13. Clock disagreement            | App wall clocks differ; Redis jumps affect refill                                | NTP offset and host clock alarms                           | Redis TIME; app monotonic lease deadlines; clamp backwards; conservative TTL padding                                                | Lease deadline and refill tests; injected Redis wall jumps remain untested; forward jump can admit early                                                                                                           |
| 14. Recovery retry storm          | Clients synchronize retries after outage or 429                                  | Offered/achieved RPS, queued threads, dropped iterations   | Retry-After for known 429, caller jitter only for new business attempts; no automatic ambiguous consume retries; concurrency bounds | Burst script; whole-fleet recovery drill remains                                                                                                                                                                   |
| 15. Spoofed identities            | Body/header tenant forgery or proxy headers bypass isolation                     | JWT errors, 400 unknown fields, admin audit                | Validate issuer/audience/signature; use signed claims; ignore forwarded headers; scoped evaluator/admin                             | HTTP security/spoofing tests; real production issuer configuration requires review                                                                                                                                 |
| 16. Millions of unique keys       | Authorized identity/endpoint churn exhausts memory                               | Index ZCARD, memory ratio, capacity errors                 | 100k index cap/domain, 8KiB bodies, bounded names; account issuance controls; noeviction; avoid raw path identities                 | Real 100k cap test; saturation fairness remains imperfect and OPEN bypasses guard intentionally                                                                                                                    |
| 17. Mixed versions                | Different scripts/key schemas/JSON interpretations                               | Release labels, policy parsing errors, canary mismatch     | Backward-compatible namespaces and script return contract; canary, drain; never change key format uncoordinated                     | Two adapter instances share namespace test; true two-binary rollout drill remains                                                                                                                                  |
| 18. Deleted policy, live state    | Erasing state could refill when restored                                         | Audit tombstones, TTL/index occupancy                      | Disable without deleting bucket; old state expires; reenable uses stable keys if still live                                         | CRUD disable and no-reset capacity tests; removal propagates asynchronously                                                                                                                                        |
| 19. Response times out app-side   | Accepted business operation may not run; quota reserved                          | Correlated HTTP trace and Redis timeout/error              | No compensating refund; caller must make business mutation idempotent independently of limiter                                      | Timeout tests; gateway cancellation after Redis success remains a drill                                                                                                                                            |
| 20. Abrupt Kubernetes termination | Inflight socket closed; leases lost                                              | Termination/restart metrics, 503/connection resets         | Graceful shutdown20s, termination grace30s, readiness removal, PDB; no lease refunds                                                | Manifests verified, termination drain under traffic not executed; SIGKILL loses inflight responses                                                                                                                 |

Redis error classification matters: quota denial is 429; command/connection uncertainty is 503 under CLOSED; fail-open
emits `mode=fail-open` and suspends quota guarantees. Stale policy and cardinality failures are conservative refusal,
not proof of Redis hardware failure, though the broad dependency-failure metric currently groups them. TLS/network
partition cannot be solved with retries on non-idempotent deduction.
