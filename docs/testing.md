# 5. Test strategy and actual verification

Run `mvn -B -ntp verify` for fast tests and `mvn -B -ntp -Pintegration verify` for the full real-dependency suite.
Integration tags are explicitly excluded from the default build; the integration profile enables them and excludes
diagnostic benchmarks. Missing Docker causes the integration run to fail rather than silently skip.
`mvn -Pbenchmark test` runs the separate external-Redis diagnostic only.

The full suite executed under Oracle JDK 21.0.13.0.3, Maven 3.10.0, Docker 29.8.2/OrbStack, Redis 8.2.11 and PostgreSQL
17.12. **35 tests passed, zero failures/errors/skips** in the final full integration run. The separate adapter
comparison is one benchmark test and is not counted in those35. The image build also executes the fast test subset.
See [verification evidence](../benchmarks/results/verification.txt) and Maven `target/surefire-reports` for generated
reports.

Property testing uses seeded randomized invariant loops without an additional property-testing library. Local balance
never exceeds capacity or goes negative and total accepted cost stays within C+rΔ. Redis randomized tests hold elapsed
refill below one token and verify accepted cost <=C; concurrency tests use a very slow refill so no full token appears
during the test. Tests use actual Redis for distributed-state claims, never mocks as atomicity evidence.

Tests discovered and drove fixes for configuration binding, lease warmup/deadline behavior, restart reconnect mapping,
refill-rate changes after rejection, and cross-policy bucket/lease isolation. Controlled Redis restart shows both
graceful persistence preservation and deliberate state loss with persistence disabled; it does not prove sudden
power-failure durability.

Required additional production drills: OOM/wrong-type injection and partial-write handling, induced replica-lag
rollback, abrupt primary death during consume, live ASK/MOVED reshard load, network partition, 1000 real pods, key churn
fairness, frozen/forward Redis clocks, mixed binaries, killed lease holders, termination drain, HPA recovery storm, DB
backup restore, two-region partition/budget transfer, and long soak with production TLS/JWT/observability. Exact
commands for representative load are in benchmark documentation; fleet-specific chaos tooling must target a disposable
staging environment.
